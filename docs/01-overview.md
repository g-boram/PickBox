# 01. 기획 · MVP 범위

## 한 줄 소개
중고거래 판매자가 물건을 무인 보관함에 맡기면, 구매자가 앱의 QR로 찾아가는 서비스.

## 문제
| 문제 | 지금의 방법 | 불편함 |
|---|---|---|
| 직거래 시간 맞추기 | 채팅으로 약속 | 서로 일정이 안 맞음, 노쇼 |
| 낯선 사람 대면 | 공공장소에서 만남 | 심리적 부담, 안전 걱정 |
| 고가 물품 택배 | 택배 거래 | 분실·파손 위험, 포장 번거로움 |

## 해결
- 판매자는 **아무 때나** 보관함에 맡긴다
- 구매자는 **아무 때나** 찾아간다
- 맡긴 순간·찾아간 순간이 기록되어 **"물건 받았다/안 받았다" 분쟁을 줄인다**

## 사용자와 권한
| 주체 | 사용하는 곳 | 할 수 있는 일 |
|---|---|---|
| 사용자 | **앱만** | 회원가입, 로그인, 거래 등록(판매자), 거래 참여(구매자), QR 발급 |
| 관리자 | **웹만** | 칸 상태·거래 현황·보관/수령 기록 확인 (회원가입 없음, 미리 생성된 계정) |
| 키오스크 | 태블릿 | QR 확인 요청, 문 열림/닫힘 보고 (기기 키로 인증) |

한 사용자 계정이 어떤 거래에서는 판매자, 다른 거래에서는 구매자가 될 수 있다.

## MVP 범위 (처음 만들 것)
### 포함
- **앱**: 회원가입/로그인, 거래 등록, 거래 코드로 참여, 내 거래 목록·상세, 맡기기/찾기 QR 발급
- **키오스크**: QR 스캔, 칸 배정 안내(화면 + 음성), 문 닫힘 감지 후 완료 처리, 사람 접근 시 "어서오세요"
- **보관함**: 3칸, 칸마다 LED + 문 센서, 인체감지 센서 1개 (**잠금장치 없음**)
- **관리자 웹**: 로그인, 대시보드(칸 상태), 거래 목록·상세(타임라인), 이벤트 기록

### 제외 (확장 단계로)
- 결제 / 안전결제(에스크로) — MVP에서는 대금은 앱 밖에서 주고받는다
- 실제 잠금장치(솔레노이드)
- 푸시 알림 (MVP는 앱에서 새로고침으로 상태 확인)
- 물품 사진, 채팅, 보관료, 여러 지점
- 키오스크 원격 관리, 자동 업데이트

## 성공 기준 (MVP 완료 조건)
1. 판매자·구매자 두 계정으로 **거래 등록 → 보관 → 수령**이 실물 보관함에서 끝까지 동작한다
2. 관리자 웹에서 그 과정이 **실시간에 가깝게** 보인다
3. **웹은 배포된 URL**, **앱은 스토어(테스트 트랙 이상)**, **키오스크는 서명된 APK**로 배포되어 있다

## 확장 아이디어 (몸집 키우기)
| 우선순위 | 기능 | 배우는 것 |
|---|---|---|
| 1 | FCM 푸시 ("물건이 보관되었어요") | 푸시 인프라, 서버→앱 이벤트 |
| 2 | 키오스크 모드 (HOME 런처, Lock Task, Device Owner) | 안드로이드 시스템 영역 |
| 3 | 잠금장치 (릴레이 + 솔레노이드) | 전원 분리, 릴레이 회로 |
| 4 | 칸 안 물품 감지 (초음파 / 무게) | 센서 판단 로직 |
| 5 | 키오스크 자동 업데이트, 원격 재시작 | OTA, 기기 관리 |
| 6 | 보관 기간 초과 처리, 보관료 | 스케줄러, 정책 설계 |
| 7 | 안전결제 (토스페이먼츠 테스트 모드) | 결제 연동, 에스크로 흐름 |
